# LOCAL LLM NEWS 🌟

ローカルLLMの最新情報を毎朝自動更新するネオンライト風ニュースサイトです。

## 構成

```
.
├── index.html                      # サイト本体（news.json を読み込んで表示）
├── news.json                       # ニュースデータ（毎日自動更新）
├── update_news.py                  # ローカルLLMでニュースを更新するスクリプト
├── scripts/run_local.sh            # 毎朝cronで実行（pull → 更新 → push）
├── scripts/.env.example            # LLMサーバーなどの設定例
└── .github/workflows/
    └── update-news.yml             # 手動実行用
```

## 自動更新のしくみ（ローカルLLM）

毎朝 **7:00 JST**、自宅の常駐機（Mac mini）が `scripts/run_local.sh` を実行し、
DGX Spark で動くローカルLLM（OpenAI互換API）がニュースを選定・要約して `news.json` を更新します。

1. DuckDuckGo News と RSS/Atom（Hugging Face Blog、Ollama・vLLM のリリース、r/LocalLLaMA など）で直近の候補を集め、掲載済みと重複を除く
2. LLMが候補一覧から載せる記事を最大6本と注目記事を選ぶ（候補IDで返すのでURLは創作できない）
3. 記事ページの本文を取得し、LLMが1本ずつ日本語で要約（URLと日付はプログラムが埋める）
4. LLMがティッカーを作り直す
5. 全体を検証して `news.json` を原子的に保存（1件でも不正なら保存しない）

ランキング（`ranking_*`）は自動では書き換えず、そのまま引き継ぎます。

### 日本語用途ランキングの決め方

- 重みが公開されているモデルを、[Swallow LLM Leaderboard](https://swallow-llm.github.io/leaderboard/index-post.ja.html)（東京科学大・産総研、CC-BY 4.0）の事後学習モデル・日本語タスク平均で並べています。SCOREはその平均×100です。
- 同じ開発元のモデルは最高スコアの1つだけを載せます。
- リーダーボード未評価のモデル（LLM-jp-4.1、ELYZA-Thinking-1.0 llm-jp-4版、PLaMo 3系など）は、評価が出たら入れ替えます。

## セットアップ（Mac mini などで）

```sh
git clone git@github.com:datamonsters-jp/local-llm-news.git && cd local-llm-news
python3 -m venv .venv && .venv/bin/pip install ddgs
cp scripts/.env.example scripts/.env   # LLM_BASE_URL / LLM_MODEL / LLM_API_KEY を書く
.venv/bin/python update_news.py --dry-run   # 書き込まずに試す
scripts/run_local.sh                        # 本番（更新してpush）
```

毎朝7時に回すには cron に登録します（マシンのタイムゾーンがJSTの場合）:

```
0 7 * * * /path/to/local-llm-news/scripts/run_local.sh >> /tmp/local-llm-news.log 2>&1
```

push には、このリポジトリだけに書き込める **Deploy key**（Settings → Deploy keys、Allow write access）を使うのがおすすめです。

## オフライン検証

Node.js 20以上とPython 3.10以上で、APIキーなしで検証できます。

```bash
npm ci
npm test
```

DOMテストはjsdomで生成テキストの安全な描画、URL・スキーマ検証、日付順、取得前のタブ選択、取得失敗、再試行、既存データ維持を検証します。PythonテストはLLMをモックし、選定・要約・データ検証と原子的保存を検証します。実際のLLMやネットワークは使いません。

任意のブラウザ回帰テストはPlaywrightとChromiumがある環境で `node tests/browser.cjs` を実行できます。システムChromiumを使う場合は `CHROMIUM_PATH` を指定してください。このテストは外部通信を遮断し、ローカルのfixtureで応答します。

### データの扱い

- 生成データはHTMLとして挿入せず、テキストノードと解析済みHTTP(S)リンクとして描画します。
- 新規生成データの必須項目・日付・スコア・URLを検証し、不正なら更新全体を中止します。既存のファイルを切り詰めません。
- 新規モデルのリリース日は `YYYY.MM` 必須です。表示側は既存データの年だけの値もその精度のまま表示し、月を推測しません。
- ニュースは日付の降順に表示し、同日の記事順と全件を維持します。過去の更新分を蓄積する機能は含みません。
- ランキング取得中・失敗時は保存データを維持し、状態と再試行ボタンを表示します。保存されていない用途を取得前に選ぶと、選択を維持したまま通常用途の保存データを明示して表示します。
- 固定アーカイブ全16件を保持。一次資料で確認できたリンク・記述・日付を修正し、確認できない記事は未検証と明記して無関係なリンクを非表示にしています。


## ランキングのPC・メモリ目安

`hardware-guidance.json` は日次生成する `news.json` と分離した、手動確認のカタログです。モデル名の完全一致（大小文字・連続空白のみ正規化）で照合します。生成された数値・追加フィールドからPC構成を推定しません。

- 現行24種類のうち21種類に資料に基づく案内を用意しています（容量・構成の目安20種類、重み公開待ち1種類）。残る3種類は公式配布とモデル名を照合できず「モデル名を確認」です。新規の未登録モデルは「確認中」です。全モデルの仕様・順位・ベンチマークを検証済みという意味ではありません。
- 「推定」「メーカー対応情報」「サーバー級」「重み公開待ち」「対応状況に注意」「モデル名を確認」を区別します。当サイトで推論速度の実測はしていません。
- Mac mini 16GB / Mac Studio 48GB は容量からの概算例です。必要最小容量や動作・速度の保証ではありません。DGX Spark 128GB のScout例はNVIDIAの指定NVFP4版とTensorRT-LLMの対応情報に限定します。
- 重みだけのGB、GPUのVRAM、OSと共有する統合メモリを区別します。KVキャッシュ・作業領域・画像入力・長文・同時実行の追加容量が必要です。MoEのアクティブ数を全重み容量として扱いません。
- 各登録に量子化、ランタイム、条件、確認日、一次資料を保持します。新しいモデルは確認してからカタログに追加し、実測がなくても、モデル規模・量子化配布が確認できれば「推定」として大まかな容量帯を示します。モデル自体の識別や配布形式が不明なら数値を埋めません。
- カタログ取得・検証の失敗でもニュースの取得を止めません。専用の再読み込みで復旧できます。日次更新はカタログを書き換えません。
- 自動生成のreason/badgesにメモリ・PC/GPU/CPU構成・速度などの記載がある場合、表示側でその理由・バッジを抑制し、確認済みカタログへ案内します。無害なハードウェア関連説明も隠れる場合があります。日次更新を新しい文章ルールで失敗させることはありません。これは事実確認の代用ではなく、既存のURL・日付・スキーマ検証は変更していません。

カタログを更新したら `npm test` を実行してください。既存DOMテストに加え、カタログの値・出典URL・重複別名、未知モデル、生成フィールドの分離、両方の取得順序、失敗・再試行、タブと詳細表示、保存データ保持をAPIなしで検証します。

### 推定の前提

一般的な目安は4bit系の指定配布・テキストのみ・約4Kコンテキスト・同時利用1件です。例外は各カードに明記します。配布サイズにOS・KVキャッシュ・作業領域の余裕を見込み、8〜16GB、32〜48GB等の幅または余裕ある構成例で表します。配布サイズを実行時RAMや重みのみのGBとは同一視しません。全体の一律式だけで互換性・速度を保証せず、MoEの追加埋め込み等も個別に考慮します。

名称を照合できていない3件（Code Llama 4 70B / Code Llama 4 34B / Qwen3-72B）は別モデルへ自動で読み替えません。確認済み一覧へのリンクと理由を表示し、名称確認前の性能説明・サイズ・スコア・リリース月を表示側でも抑制します。既知の3名称は小さな安全リストにも保持し、資料取得前や取得失敗時にも抑制します。このリストとカタログの一致を回帰テストで確認します。
